$ARGUMENTS 를 Repopolis 그림 규칙대로 그린다. **모양이 곧 정보다.** 건물 높이 = 줄 수, 차 = 커밋, 사람 = 파일 수, 크레인 = 커밋 안 된 변경. 새 그림은 먼저 무엇을 알려 주는지 정하고, 장식만 하는 그림은 묻고 넣는다.

## 입력

- 필수: 그릴 것과 그것이 알려 주는 것 (예: 공사 인부 = 이 파일을 지금 고치는 중, 인부 수 = 바뀐 줄 수).
- 먼저 볼 것: `viewer.html` 의 기존 모양 함수 — 사람 `makeHoodie` · `poseHoodie` · `gait` · `BODY`, 행인 `pp`(부위마다 InstancedMesh), 크레인 `makeCrane`, 소품 `props`, 색 함수 `soft` · `softOf`, 건물 종류 `TYPES`. 같은 일을 하는 모양이 이미 있으면 그걸 고친다.

## 1. 계획 (그리기 전에 표로)

```
| 대상 | 상태 · 동작 | 알려 주는 것 | 크기 (키 단위, 사람 키 0.55) | 개수 상한 | 그리는 법 (Mesh · InstancedMesh) | 색 | 그림자 |
```

- **개수가 많으면 InstancedMesh.** 파일 수 · 커밋 수에 따라 늘어나는 것(사람 · 차 · 인부)은 부위마다 InstancedMesh 하나에 행렬로 (`pp` 방식). 하나씩 Mesh 로 만들면 큰 저장소에서 그리기 호출이 수천 개가 된다.
- **그림자는 비싸다.** 많은 것은 실제 그림자 대신 발밑 동그란 그림자(`pp.blob`)로. 주인공 · 크레인처럼 적은 것만 진짜 그림자.
- 색은 기존 팔레트(`HOODS` · `SKIN` · `SHOES`, 크레인 `YELLOW`, 공사 땅 `LOT.work`)에서 고른다. 새 색은 이유와 함께 묻는다. 의미 지키기: 주황 · 노랑 = 공사, 빨강 = 위험 · 경고.
- 상태가 둘 이상이면(일하는 중 · 쉬는 중, 공사 · 준공) 상태마다 한눈에 달라 보이는 점 하나를 정한다. 색만으로 구분하지 않는다 (모양 · 움직임으로도).
- 개수 상한을 정한다 (예: 크레인 30개). 상한을 넘으면 무엇을 먼저 보여 줄지(줄 수 큰 순 등).

이 표를 보여 주고 진행한다.

## 2. 그리기

- 모양은 `BoxGeometry` · `SphereGeometry` 같은 기본 도형을 조합해 코드로. 사람 부위는 `BODY_GEO` · `BODY_GEO_LO`(멀리 · 많을 때 낮은 품질)를 다시 쓴다.
- 처음엔 숨겨 두는 것도 시작할 때 셰이더를 미리 만든다 (`warm` 이 숨긴 것까지 컴파일). 새 재질을 동작 중에 처음 만들면 그 순간 멈칫한다.
- 움직임은 그리기 반복(`setAnimationLoop`)에서 시간으로 — 프레임 수가 아니라 `dt` · `time`. 자세는 매 프레임 처음부터 다시 정한다 (`poseHoodie` 는 위치 · 회전을 모두 되돌린다 — 더하기만 하면 쌓여서 몸이 분리된다).
- 실시간 갱신(`applyLive`)에서 바뀌는 것이면(공사 중 파일 목록 등) 다시 세우는 함수(`rebuildCranes` 처럼)를 두고, 버린 재질은 `dispose`.

## 3. 확인

실험실 사진: `npx electron .claude/lab/lab.js <html> shot <스크래치 폴더>` (낮 · 밤 · 걷기 · 건물 안). 잠깐만 보이는 것은 `#debug` 의 `__rp` 로 그 상태를 만들고 `capturePage` 로 찍는다.

| 확인 | 기준 |
| ---- | ---- |
| 낮 · 밤 | 둘 다 바탕과 구분됨 (밤엔 불빛 · 테두리) |
| 멀리 (둘러보기) · 가까이 (걷기) | 멀리서도 무엇인지, 가까이서 이음새가 안 벌어짐 |
| 작게 보기 | 사진을 절반으로 줄여도 무엇인지 · 어느 상태인지 알아봄 |
| 큰 저장소 | `/playtest` 의 큰 저장소에서 그리기 호출(`calls`) · 멈칫이 크게 늘지 않음 |
| 주인공과 겹침 | 걷는 길을 막지 않음 (막아야 하면 `blocked` · 받침 `addPlat` 에 넣음) |

전 · 후 사진을 나란히 보고서에 둔다. 사진은 스크래치에 두고 커밋하지 않는다.

## 4. 마무리

- `/playtest play` 를 큰 저장소 하나 이상에서 돌려 멈칫 · 그리기 양이 늘지 않았는지.
- README 의 "도시 읽는 법" 표에 새 모양이 알려 주는 것을 한 줄.

## 하지 않는 것

- 이미지 · 3D 모델 파일, 이미지 생성 API (유료), 새 라이브러리를 묻지 않고 추가
- 정보 없는 장식을 묻지 않고 많이 넣기
- 사진 확인 없이 "잘 보인다"고 보고

## 출처

link-dungeon 의 `/game-art`(계획 표 → 그리기 → 사진 확인, 상태마다 달라 보이기, 작게 봐도 읽히기, 색 말고 모양으로도 구분)를 Repopolis 의 three.js 도시에 맞게 고쳐 썼다. 그 원본은 sprite-gen(aldegad, Apache-2.0)의 품질 검사와 Claude-Code-Game-Studios(Donchitos, MIT)의 art-bible 규칙을 참고했다.
