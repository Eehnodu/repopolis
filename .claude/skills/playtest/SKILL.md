$ARGUMENTS 의 저장소를 도시로 열어 정해진 플레이를 재서 보고한다. **잰 것만 쓴다.** 못 연 저장소 · 못 돌린 단계는 "판단 안 함"으로 남기고 통과로 쓰지 않는다. 숫자 하나가 좋아 보여도 사진과 같이 확인하기 전에는 "됨"이라 하지 않는다.

## 입력

- 모드 (비우면 `full`):

| 모드 | 하는 일 |
| ---- | ---- |
| `scan` | 2단계만 (도시 만들기 시간 · 크기) |
| `play` | 3단계만 |
| `full` | 2 · 3 · 4단계 |
| `human` | 6단계. 사람이 직접 하고 소감을 받는다 |

- 저장소: 경로 목록, 또는 `기준선` = [repos.md](repos.md). 목록이 다르면 전후 비교를 하지 않는다.
- 있으면 좋은 것: 이번에 바꾼 것(무엇을 보려는지), 비교할 이전 보고서.

## 1. 준비

- 도시 HTML 은 `node scan.js <저장소> -o output/pt-<이름>.html --no-open` 으로 만든다 (`output/` 은 git 에 안 들어간다). 앱(`app/main.js`)과 같은 화면 코드(`viewer.html`)를 쓰므로 화면 쪽은 앱과 같다. 앱에만 있는 것(실시간 감시 · 트레이 · 새 버전)은 이 방법으로 못 잰다 — 필요하면 4단계.
- 재기는 `npx electron .claude/lab/lab.js <html> play <out.json>`. 화면 밖에서 돈다 — 사용자 창에 가려져도 느려지지 않지만 fps 는 실제 창보다 낮다. **fps 는 같은 조건 전후 비교에만** 쓰고, 멈칫(100ms 넘는 한 프레임) · 움직인 거리 · 오류를 본다.
- 한 번에 하나씩 돌린다 (메모리). 저장소마다 2분 안쪽.
- 화면 밖 창은 **첫 키 입력 한 번이 200~300ms** 걸린다 (실제 창에선 없음). `lab.js` 는 재기 전에 아무 일 없는 키(F24)를 한 번 누른다. 직접 스크립트를 쓸 때도 그렇게 — 안 그러면 "첫 동작에서 멈칫"을 잘못 찾는다 (2026-10-21, 밤 전환 · 첫 점프 멈칫으로 잘못 봄).

## 2. 도시 만들기 (`scan`)

| 항목 | 재는 법 | 문제로 보는 기준 |
| ---- | ---- | ---- |
| 만들어짐 | `scan.js` 끝남 · 종료 코드 | 멈추거나(2분 넘음) 오류면 이유만 적고 다음 저장소 |
| 만드는 시간 | `scan.js` 실행 시간 | 같은 저장소의 이전 값보다 크게 늘면 기록 |
| 크기 | 건물 수 · 줄 수 · 커밋 수 (scan 출력), HTML 크기 | 문서(.md)가 건물로 들어왔으면 기록 |

## 3. 플레이 (`play`)

`lab.js play` 결과 JSON 한 개가 한 저장소다.

| 항목 | JSON | 문제로 보는 기준 |
| ---- | ---- | ---- |
| 켜지는 시간 | `loadMs` | 큰 저장소에서 5초 넘음 |
| 그리기 양 | `city.calls` · `city.tris` · `city.programs` | 이전보다 크게 늘면 기록 |
| 동작별 멈칫 | `steps[*].maxMs` · `over100` | 100ms 넘는 한 프레임. 건물 들어가기(화면이 검은 동안)는 제외 |
| 걷기 막힘 | `walk.movedM` | 11초 걷고 3m 안 → 시작 자리가 갇힘 |
| 들어갔다 나오기 | `inside` 가 `inside`, `after` 가 `orbit` | 아니면 실패 |
| 오류 | `errors` | 하나라도 있으면 기록 (같은 오류는 묶어서 개수) |

저장소마다 한 줄 표로 모으고, 문제 칸만 굵게.

## 4. 사진 · 앱 확인 (`full`)

- 사진: `npx electron .claude/lab/lab.js <html> shot <스크래치 폴더>` → 낮 · 밤 · 걷기 · 건물 안. 저장소마다 한 번 보고, 이상한 것(빈 땅 · 겹친 건물 · 묻힌 주인공 · 밤에 안 보임)만 보고서에 사진과 함께.
- 앱에서만 되는 것(실시간 감시 · 새 버전)은 `app.setPath('userData', <스크래치>)` 로 설정을 따로 둔 뒤 `require('app/main.js')` 하는 작은 스크립트로 띄운다. 설치된 Repopolis 와 설정 · 단일 실행 잠금을 나누지 않게. 띄운 프로세스는 PID 로만 끈다.

## 5. 전후 비교

같은 기준 목록 · 같은 컴퓨터에서 잰 이전 보고서가 있으면 저장소마다 `loadMs` · 동작별 `maxMs` · `movedM` · 오류 수를 나란히. 한 번만 잰 멈칫 차이는 흔들릴 수 있다 — 두 번 재서 둘 다 나빠졌을 때만 "나빠짐".

## 6. 사람 플레이 (`human`)

봇으로 못 재는 것(재미 · 길 찾기 · 눈에 띄는가)은 사람에게 묻는다. 체크리스트를 주고 소감을 문장으로 받는다.

- 처음 켜서 30초: 무엇을 보는 화면인지 알겠는가, 내 파일 하나를 찾을 수 있는가
- 걷기 3분: 가고 싶은 건물에 갈 수 있는가, 갇히거나 카메라가 답답한 곳
- 건물 안: 코드 보기까지 몇 번 눌렀나, 나오는 길이 보이는가
- 고치는 중(공사): 바뀐 파일이 눈에 띄는가

소감 문장은 `/feel` (손맛) · `/game-review` (규칙 · 목표) · `/game-art` (모양)로 나눠 넘긴다.

## 보고

결론 한 줄(가장 큰 문제 하나) → 2단계 표 → 3단계 표 → 4단계 사진 · 앱 확인 → 5단계 비교 → 판단 안 함 목록. 보고서는 스크래치에 두고 커밋하지 않는다.

## 하지 않는 것

- 코드 수정 (재고 보고만)
- 화면 밖 fps 를 실제 성능처럼 쓰기, 한 번 잰 숫자로 "나빠졌다" 단정
- 설치된 Repopolis 를 이름으로 끄기 · 그 설정 폴더 건드리기

## 출처

link-dungeon 의 `/playtest`(기준 목록 · 잰 것만 쓰기 · 판단 안 함 · 전후 비교 · 사람 플레이)를 Repopolis 의 저장소 → 도시 구조와 실험실에 맞게 고쳐 썼다.
